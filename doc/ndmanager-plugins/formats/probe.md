# `.probe` — probe configuration (YAML)

Read by `ndm_setupgroups`, `ndm_estimatedrift`, `ndm_driftcorrect`,
`ndm_localise`, Klusters (drift views) and the ndmanager probe pages.
Stored in the probe library at `${CMAKE_INSTALL_DATADIR}/neurosuite/probes/`.
Entries in the session YAML `probes:` section reference files by path
relative to the library root (e.g. `neuronexus/Buzsaki64.probe`).

## Layout

```yaml
probeFile:
  version: '1.0'
  vendor: NeuroNexus
  model: Buzsaki64
  catalogPage: 101          # page of the vendor catalogue the numbers come from
  totalChannels: 64
  substrate: {material: silicon, thickness_um: 15}
  shanks:
    count: 8
    spacing_um: 200         # centre to centre; null for one shank
    length_mm: 5.0
  sites:
    count_per_shank: 8      # or one entry per shank: [10, 10, 10, 14, 10, 10]
    layout: octrode         # linear | edge | poly2 | tetrode | octrode
    area_um2: 160
    spacing_um: null        # vertical step for single-column / poly2 layouts
    geometry:               # [x_um, y_um] per site — see below
    - [-20.7, 162]
    - …
  channelMap: {description: null, map: null}
  notes: '…'
```

## Geometry and channels

`sites.geometry` lists every site, **shank by shank** (left to right), and
within a shank **top site first, tip site last**:

- `y` — height above the shank's tip apex, µm (so the deepest site has the
  smallest `y`);
- `x` — lateral offset from the shank's tip axis, µm, plus
  `shank_index × shanks.spacing_um`.

Site *j* of the file belongs to channel `channelOffset + j` of the session
(`probes[].channelOffset`), or `channelOffset + channelMap.map[j]` when a map
is given (a flat list, or one list per shank).  With the library files
(`map: null`) the channel numbers therefore **ascend as the sites go deeper**
on every shank, e.g. Buzsaki64 shank 0: channels 0…7 at y = 162, 142, …, 22.
The recording is assumed to be in this channel order already (remapped from
the headstage / connector order at acquisition or conversion).

Every tool looks a channel's position up by channel number
(`scripts/probe_geometry.py`; Klusters' `driftgeometry.cpp`), so spike groups
may list their channels in any order.

`count_per_shank` decides which geometry entries belong to which shank; it is
a list when the shanks differ. A one-shank probe may leave it out (or null):
every geometry entry is then a site of that shank. A multi-shank probe needs
it.

## NeuroNexus library

The files in `probes/neuronexus/` are generated by
`src/nphys-data/tools/neuronexus_probes.py` from a table of catalogue
dimensions (NeuroNexus *Penetrating Probes*, August 2025), with the page of
each design in `catalogPage`.  Edit the table, not the files;
`neuronexus_probes.py --check DIR` lists files that differ from it.
Offsets inside octrode / staggered clusters are not labelled in the
catalogue and were measured from the drawings; the notes of each file say
so.
